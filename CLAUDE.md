## What this repo is

Production pipeline for a solo lofi-jazz YouTube channel (first channel: "Jazzt a Pengui"). Three independent systems:

1. **n8n workflows** (`workflows/*.json`) running on the author's n8n server. Editing the files changes nothing live — the author re-imports them manually.
   - `10_Единый_редактор.json` — main Telegram bot: one "Editor" (OpenAI `/v1/responses`, one conversation per project) drives picture → text block (8 numbered items) → final summary → approval → sheet. **Generated — never edit by hand** (see below).
   - `04_Video.json` — takes approved project + tracks zip, calls the assembler, uploads to YouTube (timecodes, tags).
   - `11_Календарь.json` — calendar of episode occasions.
   - `00`–`03`, `99` — older workflows; `00` and `10` share one Telegram bot webhook, so only one of them may be active.
2. **Assembler** (`assembler/app.py`) — Flask + ffmpeg service on Coolify: `/assemble`, `/trackinfo`, `/thumbnail/<id>`, `/health`. Bump `ASSEMBLER_VERSION` on every change; `/health` reports it. The author deploys it herself (`wget -O /app/app.py <raw url of this branch>` then Restart, not Deploy — `/app` is persistent storage untouched by Deploy).
3. **Google Sheet** `1yEolX-8NV7NInu3OwCoxo2KSSNMny9dk-AVrpKdyNEs` — the control panel. `Templates` sheet holds per-channel settings/prompts (column prefixes: 🖋 text/Editor, 🎨 picture, 🎬 assembler); one sheet per channel holds project rows (`sys_*`, `ai_*`, `fx_*` columns; `sys_EditorState` is JSON state). `table_drafts/` holds drafts of long cells for the author to paste.

## Core rule: code is mechanics only

Everything creative or channel-specific (tone, style, prompts, character, reference images and their roles, image model, sound/overlay numbers) lives in the Sheet, never in code. No channel names or content ("Pengui" etc.) in code. Code changes to workflows or the assembler only after the author's explicit "да"; show a summary/diff first.

**Author's requirement: the column icon is the recipient.** In Templates, 🖋 = Editor, 🎨 = artist, 🎬 = assembler (and the Writer gets its own icon). A column reaches a recipient if and only if it carries that recipient's icon; code never picks columns by name on its own. Removing an icon must stop that recipient from seeing the column. (As of 03.10 the code does not yet fully honour this — see PROJECT_NOTES.)

## No settings or content words in code — the guard (28.10)

Code is routing only: it addresses categories and participants. Every number, word, default, model name and channel name lives in the Sheet. Missing column = no processing (or a clear «Таблица: …» message), never a fallback value in code.
- Effects: words of the markup language (пар, густота, клён, обложка Б…) live in the sheet «Эффекты», columns «Слово» → «Значит» (one sheet for effects; sections Анимация / Звук); the assembler only knows the values (steam, density, maple, B…) via `to_ids()`. 04 and 12 pass them as `fxWords`. Knobs: any number (fractions, below 0); 5 = base, every 5 steps doubles or halves; 0 never means off.
- Sound, overlay, frame, theme mark, effect timing — 🎬 columns in Templates (see Бэкапы row 69 for what moved).
- `python3 tools/guard/guard.py` must say «нарушений: 0». Allowed technical items are listed one by one, with a reason, in `tools/guard/allow.txt`; settings and content words never go there.
- Effect parsing parity: `python3 tools/effects/fx_parse_dump.py assembler out.json tools/effects/slova.json` over `tools/effects/fx_corpus.json` (real episode lines).
- Assembler tests: `python3 tools/assembler_sound_test.py`, `python3 tools/assembler_tablica_test.py`.

## Reliability rules (24.10, after the audit `docs/AUDIT_24-10.md`) — one rule per class, no per-case patches

1. **Locks by deed, held on the server.** Anything that must not run twice at once takes a key on the assembler's `/gate` (`lock: true` → `locked`; `release: true` when done; TTL as the safety net). The Google Sheet is a record for the author, never a lock: an execution sees the row as it was when it started. Workflow 12 (28.10): one queue `/inbox` on the assembler for everything the bot receives — «Приёмная» puts it (dedupe by key, one job per episode at a time, the rest wait), runs «Работа» (the same canvas called by itself and awaited), then `done` (+ next of the episode) or `fail` (quiet retries 1/3/10 min, fatal → author at once). Every Wait node in «Работа» must release the queue first (`done`) — see «Очередь: отпускаем (Kaggle)».
2. **The one who knows the truth decides.** Cleaning: Kaggle/the server knows; «блокнот занят» never writes the project row.
3. **Retries only where repeating is harmless:** sheet reads, sheet updates by key, stateless requests, GET/PUT/DELETE. Code nodes DO retry (3×25 s: no side effects; without it a runner timeout fails the run and Telegram redelivers — a loop). Never on Telegram sends, sheet appends, OpenAI calls that keep a conversation, `/clean_start`, `/gate`. `check12.py` enforces it for 12; `tools/patch_retries.py` for 14. Workflow 04 keeps its retries everywhere (author, 24.10: no duplicate upload ever happened).
4. **No silent dead ends.** Every Switch output leads somewhere, except the ones listed in `check12.py` QUIET (silence there is deliberate).
5. **n8n server settings are part of the system.** As of 24.10 evening (see `docs/HANDOFF_24-10.md`): `N8N_RUNNERS_MODE=internal`, no task-runners container, NO pruning lines (aggressive pruning of two weeks of history pegged the n8n main thread at 100% — never enable it during the day; if ever, only with the default 14 days). Morning original: `compose_backup/n8n_compose_WITH_DNS.yml`. Change ONE setting at a time and check n8n CPU (`docker stats`) and runner errors (`grep -cE "timed out|Offer expired"`) before the next.
6. Before a fix, look for the class of problem, not the single case; a new guard is allowed only if it is one of the rules above.

## Generator for workflow 10

`tools/gen10/gen.py` builds `workflows/10_Единый_редактор.json` from `tools/gen10/js/*.js` (each JS file is the body of one n8n Code node; `lib_state.js` is prepended to some). Drawing nodes are copied from `workflows/01_Художник.json`. Workflow: edit JS/gen.py → regenerate → check → test.

```bash
python3 tools/gen10/gen.py      # regenerate workflows/10_Единый_редактор.json
python3 tools/gen10/check.py    # node syntax, $('...') refs, connections, fan-out, orphans, credentials; expect "problems: 0"
node tools/gen10/test.js        # scenario tests for workflow 10 (Code nodes run via harness.js)
node tools/gen10/test04.js      # tests for Code nodes inside workflows/04_Video.json
python3 -c "import ast;ast.parse(open('assembler/app.py').read())"   # quick assembler syntax check
```

There is no single-test runner: tests are sequential `assert` blocks in one script. `harness.js` `run(nodeName, {nodes, input})` executes a Code node with a mocked `$('Node')`; use it to try one node in isolation.

Key flow in workflow 10: `Разбираем ответ редактора` (parse.js) → if the Editor called `commission_story`/sent `storyBrief`, a separate Writer writes the English description (`pisatel_zadanie.js`), it is translated for the author (`pisatel_perevod.js`), then merged in `Парсим ответ редактора` (pisatel_itog.js), which all downstream nodes read. The Editor performs only one tool call per turn.
